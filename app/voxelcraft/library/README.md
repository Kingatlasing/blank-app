# Local reference library

A set of reference photos and real-world dimensions bundled directly with
the app, checked *before* any live Wikipedia/Openverse lookup. The point is
reliability: a bundled entry never depends on network access, never rate
limits, and its licence has already been verified once rather than trusted
blind at generation time.

Everything in here is **generated by `tools/ingest_library.py`** — don't
edit `manifest.json`, `facts.json` or `ATTRIBUTION.md` by hand, they'll be
overwritten on the next run.

```
python tools/ingest_library.py                      # landmarks + common nouns
python tools/ingest_library.py --subjects "eiffel tower" "lighthouse"
python tools/ingest_library.py --facts-only         # dimensions, no images
python tools/ingest_library.py --dry-run            # report, write nothing
python tools/ingest_library.py --refresh            # re-do existing entries
```

For each subject the ingest finds the Wikipedia article, classifies how the
photo should be rebuilt in 3D using the *same* classifier the live app uses
(so a bundled entry behaves identically to a live lookup), pulls dimensions
from Wikidata, finds a licence-cleared photo, and writes everything below.

## Licence policy

This is deliberately **not** an attempt at "all of Wikipedia" — that's
neither storable (millions of images) nor legal to mirror wholesale. Only
images confirmed **public domain / CC0, or CC-BY with attribution
recorded** may be bundled. The ingest enforces this in `_licence_ok`:
share-alike (CC-BY-SA), non-commercial, no-derivatives and non-free/fair-use
files are rejected before download, and a subject whose only available photo
is rejected is simply left out of the library rather than bundled anyway.
Rejected subjects still work in the app — they fall through to the live
lookup or to procedural shapes, exactly as before.

`ATTRIBUTION.md` is regenerated from the manifest on every run and records
the source, creator and licence of every bundled image.

## `manifest.json` — photos

```json
{
  "park bench": {
    "aliases": ["bench (furniture)", "park bench"],
    "wikipedia_title": "Bench (furniture)",
    "image": "images/park-bench.png",
    "source_label": "Openverse photo by <creator> (CC0)",
    "source_url": "https://openverse.org/image/...",
    "license": "cc0",
    "attribution": "<creator>",
    "extract": "A bench is a long seat ...",
    "build_method_override": null,
    "height_m": null, "width_m": null, "diameter_m": null, "floors": null
  }
}
```

- `aliases`: every phrasing that should match this entry. Landmarks reuse
  the aliases already curated in `known_facts.py`, so an ingested entry
  matches everything that table matches. An alias matches when it appears in
  the subject as a whole word run, so "the eiffel tower in paris" hits the
  "eiffel tower" entry while "a cat" does not hit "cathedral".
- `image`: path relative to this directory; re-encoded to a bounded-size PNG
  so the bundle stays small and every entry loads identically.
- `source_label` / `source_url` / `license` / `attribution`: required for
  attribution — an entry is never written without them.
- `extract`: the article's intro text. Stored because the 3D-reconstruction
  method (`relief` vs `revolve`) is **re-derived from it on every request**
  rather than frozen at ingest time — so a fix to
  `research._classify_build_method` reaches bundled entries immediately,
  instead of leaving them on whatever verdict happened to be current when
  they were ingested. Re-deriving costs one regex pass over ~600 characters.
- `build_method_override`: normally `null`. Set it to `"relief"` or
  `"revolve"` to correct an entry by hand; anything else is ignored and the
  classifier decides.
- The dimension fields are whatever Wikidata had; anything missing is `null`.

## `facts.json` — dimensions

The same subjects (plus any that had usable dimensions but no bundleable
photo), holding only the Wikidata measurements. `research.fetch_blueprint_facts`
consults it *after* live Wikidata and *before* the hand-curated
`known_facts.py` table, so an offline or rate-limited app still corrects
model proportions with real numbers instead of falling back to the photo's
own framing.

## Where to run the ingest

It needs outbound access to `en.wikipedia.org`, `www.wikidata.org`,
`commons.wikimedia.org` and `api.openverse.org`. Sandboxes whose egress
policy blocks those hosts can't populate the library — run it somewhere
with real network access and commit the result. `--api-base` repoints every
endpoint at another origin, which is how the pipeline is exercised against
local fixtures without touching the real services.
